Agents Are Blind on the Web Today

Agents can write code, edit documents, manage projects — but ask one to go look something up on the web and it stumbles. Every general-purpose tool falls short somewhere.

JS-rendered pages come back empty

SPAs and data-endpoint pages return skeleton HTML — the content is filled in by JavaScript that plain HTTP never sees.

→ Built-in V8 renders for real + js_extract pulls structured data
Cloudflare / anti-bot walls

Your server IP gets 403s, or hangs on "Just a moment..." challenge pages. The workflow dies right there.

→ Automatic Turnstile waiting + switchable stealth TLS fingerprints
Read-only can't act

Fetching pages is not browsing. The moment a flow needs clicks, forms, login or pagination, scrapers are done.

→ Persistent sessions with indexed click/input — browse like a human
Search returns stale snapshots

→ Fetches the live page as it is now, not an index snapshot
Screenshots require Chromium

Vision input needs screenshots, but Puppeteer/Playwright drag in all of Chromium — too heavy for most servers.

→ Built-in Blitz rendering stack, pure CPU, zero Chromium
Raw HTML nobody can read

Generic crawlers return raw tag soup. The agent can't use it directly — someone has to clean it first.

→ Returns clean markdown, ready for the agent to consume

A Browser, Not a Search Engine

Search products give you snapshots from their index. A browser gives you the live page. An agent needs the world as it is now — not as a crawler stored it last week.

⚡ Real-time

Search indexes lag by days. We fetch the current page directly — prices, stock, statuses, latest posts. When the world changes, fetch again. Agents shouldn't see yesterday's web.

🌐 Unlimited reach

Search only covers what got indexed. A browser reaches any URL — pages behind login, JS-rendered SPAs, paginated dashboards, anything needing a screenshot. Where search can't go, a browser can.

🤝 Interactive

Search reads summaries. A browser logs in, fills forms, submits, paginates, clicks through — operating the page like a person to get results search will never surface.

Where Other Agent Browsers Hit a Wall

Most new "agent browsers" are stateless, fingerprint-less one-shot renderers — fine for public pages, useless against Cloudflare or anything requiring login. AginxBrowser goes the other way and focuses on the three things they can't do.

🔐 Real TLS fingerprints

Stealth mode uses BoringSSL to replicate the complete Chrome145 / Firefox133 / Safari / Edge TLS handshakes (not just a UA swap), switchable per request; Cloudflare Turnstile challenges wait automatically for cf_clearance. Fingerprint-less engines eat 403s — we get through.

🤝 Stateful long sessions

Persistent sessions (8-minute idle keep-alive), login state injectable and exportable (session_create(cookies=...) ↔ session_cookies). Login → paginate → act, unbroken. One-shot engines discard state and can't do multi-step flows.

🔌 MCP native

All 13 tools are first-class citizens, not a CDP shim. One line connects Claude Code / Cursor — no DevTools protocol to learn first. HTTP + MCP dual protocol, usable as-is.

Reference point: Cloudflare's Kitesurf explicitly ships neither real TLS-fingerprint negotiation nor persistent auth sessions — anti-bot and login territory is exactly where AginxBrowser plays.

Security & Privacy

An agent's browser touches your cookies and your logged-in state. It shouldn't be a black box watching you, and it shouldn't expose your internal network to the agent.

🚫 No cookie / session persistence

Injected cookies and interactive sessions live in memory only, reclaimed after 8 minutes idle. The hosted instance persists none of your login state — gone when the session ends.

🛡️ SSRF + DNS rebinding protection

Non-http(s) schemes blocked, private/loopback IPs rejected, re-validation after every DNS resolution. The agent can't reach your intranet, and DNS rebinding doesn't work either.

🔒 MCP safe on the public internet

MCP over HTTP only accepts trusted hosts by default — safe exposed to the public internet. Streamable HTTP + SSE, natively supported by Claude Code / Cursor.

👁️ Fully open source

Apache-2.0, transparent and auditable. Don't trust the hosted instance? Self-host everything locally — your data never leaves your machine.

🧩 CAPTCHA auto-solve

CAPTCHA type detection with optional 2captcha solving. Search flows stop dying on verification pages.

☁️ Cloudflare auto-wait

Detects "Just a moment..." challenge pages and waits out cf_clearance automatically, without breaking the agent's flow.

Connect Your Agent

MCP or HTTP, your pick. Claude Code / Claude Desktop / Cursor work with one line of config.

1 One-line MCP setup (Claude Code)
# Hosted instance — connect straight to the public endpoint:
claude mcp add aginxbrowser \
  --transport http https://browser.aginx.net/mcp

# Or one-command skill + MCP install (lets the agent trigger it itself):
curl -fsSL https://raw.githubusercontent.com/yinnho/aginxbrowser/main/skill.sh | bash

# Or install the skill trigger surface via skills.sh (MCP still registers separately):
npx skills add yinnho/aginxbrowser
2 Call the HTTP API directly
# Fetch a live page -> markdown
curl -sS -X POST https://browser.aginx.net/fetch \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com"}'

# Search -> merged and deduplicated
curl -sS -X POST https://browser.aginx.net/search \
  -H "Content-Type: application/json" \
  -d '{"q":"macbook price","max_results":5}'

# Capability listing (no fetching, instant)
curl -sS https://browser.aginx.net/doctor | jq .
3 Self-host
# Single binary, zero dependencies, systemd-friendly
cargo build --release --features stealth,screenshot
./target/release/aginxbrowser
