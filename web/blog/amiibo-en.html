The same 940 pages, on this Mac

AginxBrowser engineering notes · 2026-10-22 · 中文

Same Mac, same 940 pages, pool 25. AginxBrowser 0.6.2 / cec3741, three cold starts: 52.400s, 51.568s, 51.816s, peak RSS 399–405 MiB, one process. On 2026-10-21 this machine measured Obscura 0.2.5 at 54.83s and 199 MiB, one process, and Lightpanda 1.0.1 at 59.01s and 67.76s and 841 MiB, 25 processes. Those peers were not re-run on Oct 22. The 4.5s figure is their AWS table.

On 2026-10-19 Pierre Tachoire published Benchmarking AI-native headless browsers built from scratch. The table is Lightpanda, Obscura, Moli, and Cloudflare Kitesurf. AginxBrowser is absent. The task crawls the Amiibo demo: follow same-host links from the index through 940 pages, 25 at a time. The method page is their crawler benchmark. The index only exposes links after load.js runs, so a client that reads the raw HTML never sees the next page.

This page adds our column on our machine, using their public task. The numbers stay in three blocks: claims from their machine, receipts from this machine, and tests we did not run.

Obscura did not finish under official chromedp.Nodes. The finished 54.83s polled Runtime.evaluate, CPU 11.35s. That row and the Lightpanda rows are different link queries. Both finished 940/940.

The Oct 22 wall times sit under the Oct 21 same-Mac Obscura 54.83s and Lightpanda 59.01s / 67.76s. Those two were not re-run on Oct 22, so the order is only the finished receipts. Peak RSS stayed about 400 MiB. Obscura on this Mac was 199 MiB. Lightpanda was 841 MiB across 25 processes.

The crawl client did not request a screenshot. The 52 seconds do not include writing a PNG. Aginx paints screenshots in-process and does not start Chrome for that. This task did not time that path.

One run with Obscura's young-generation flags

Obscura 0.2.5's CLI sets --max-semi-space-size=4 --optimize-for-size before the first isolate. Their environment docs say --optimize-for-size then forces the semi-space cap to 1 MiB. We did not change source. AGINXBROWSER_V8_FLAGS passed that pair to the release binary already on disk. A throwaway start printed --max-semi-space-size=1, with --optimize-for-size on, and the old-space ceiling still at 3072.

/health on that run was 0.6.2 / 9df4dd8, one layout-tree commit after cec3741. 940/940, 53.402s, sampler peak 409712 KB, end-of-crawl ps 409760 KB, CPU 19.40s. The peak stayed in the 400 MiB band. Those flags did not move this crawl toward Obscura's 199 MiB. The 0.6.2 wall time to quote remains the triple above.

Which from-scratch browser is faster

On this Mac, for these 940 pages, the finished order is Aginx 0.6.2 / cec3741 at 51.6–52.4s, Obscura 0.2.5 at 54.83s, and Lightpanda 1.0.1 at 59.01s and 67.76s. The first date is Oct 22. The other two are Oct 21. Moli and Kitesurf are not in the same-machine table.

Which one uses less memory

Same-machine peak RSS, low to high: Obscura 199 MiB, Aginx about 400 MiB, Lightpanda 841 MiB. Aginx and Obscura were one process. The Lightpanda row is 25 processes. A second Aginx run with Obscura's young-generation flags still peaked at 409712 KB. The 109MB, 201MB, and 230MB figures are PSS on another machine.

Does Playwright attach by changing the endpoint

No. Aginx's public interface is HTTP: /fetch, /screenshot, and navigate, click, and eval on a session. A public CDP server is not built. Lightpanda, Obscura, Moli, and Kitesurf present CDP. That is an interface choice.

Is this the 7.6× Chrome number

Different task. The README's 7.6× against Chrome is 20 text pages from 2026-08-28. This page compares from-scratch engines on the 940-page Amiibo crawl only. Those multiples do not belong in the same sentence.

Does a default server crawl all 940 pages

No. The default is 20 pages per minute per registrable domain, plus a session page cap. The full 940 needs AGINXBROWSER_DOMAIN_RATE_PER_MIN=0 and AGINXBROWSER_SESSION_PAGE_LIMIT=0. The 429 body tells the operator to do that. The product default stays at 20.
