## 300015 是什么

- **平台业务拒绝**，不是传输层缺签。
- 深挖回执（`tmp-agent/xhs-300015-deep.json`）捕获：`publish_render` **HTTP 461**，body 大致：
  - `code`: **300015**
  - `msg`: **「浏览器运行环境异常，请关闭/卸载风险插件或重启试试」**
  - `success`: false
- UI：创建页短暂 formish → 「加载失败」→ 跳  
  `https://www.xiaohongshu.com/website-login/error?...&error_code=300015&rejectUrl=/api/edith/product/publish_render`  
  标题「安全限制」。
- **不是**未签名时的 **HTTP 406 / code=-1**（缺 `X-s`/`X-t` 会先死在签名层）。今天签过、门闩压住抢跑之后仍 300015 ⇒ 签名层已过，卡在**环境 / 风险分**。

## 已排除（勿重复绕圈）

1. **缺签 / 未装 `_webmsxyw`** → 会是 **406**，不是 300015；今天 `xs_signed` 高、`signer_ready` 有。
2. **仅 SPA 抢跑**（创建页未等签就打 `publish_render`）→ 门闩 `xs_pr_held` 生效后仍 300015。
3. **仅 `/tmp` 临时店库丢设备连续性** → 换持久库复测仍 300015。
4. **仅 Win vs Mac 人设** → `xhs-qf-stable` + Mac/145 仍 300015。
5. **仅 `x-s-common` 与重签 `X-s`/`X-t` 不一致** → `06fc061` 剥 common 后 `coherent` 仍常为 0（页面 PR XHR 往往只带 common、不带 page `x-s`），仍 300015。
6. **仅扩展探测 AbortError 面** → `aae873b` 后探针已是 TypeError/Failed to fetch，仍 300015。
7. **仅堆栈里的 diting 品牌字符串** → `7f7eca9` 后仍 300015（`tmp-agent/xhs-qf-relogin.json`）。

## 仍开放（下一棒优先）

1. **签后环境风控**：300015 文案点名「风险插件」；创建前可见多条 `chrome-extension://` 探测。面已对齐 Chrome，是否还有更深层扩展/插件指纹未证。
2. **设备 / jar 连续性 vs 丢失的 18117**：10-11 实例库已不在；今天是新稳定账号名 + 新持久库，**不等于**当年设备指纹。能否从备份恢复 18117 jar、或换仍「干净」的店做对照。
3. **页内原版 SDK vs 我们重签**：10-11 是签好后**透传页面原头**；今天 `peak_xs_passthrough` 长期为 0，门闩持有后由 recipe **重签** `X-s`/`X-t`。页面 PR XHR 常见头：`accept, content-type, x-b3-traceid, x-s-common`（无 page `x-s`）。`_webmsxyw` 只吐 `X-s`/`X-t`，**不能**mint `x-s-common`。如何让页内 SDK 自己带齐三件套再透传，是最贴近 10-11 的路径。
4. **FlClash `:7890` / TUN**：今天未用；是否与 10-11 成功环境差一截，未做 A/B。
5. **更深 AS / canvas / WebGL / 音频等指纹**，以及 **Document 导航上的 Client Hints**（HAR 快照曾怀疑 stealth 文档导航缺 `sec-ch-ua` 三件套；脚本 XHR 路径多半有引擎补发 — 优先级已下调，未闭环）。
6. **店停用 + 账号风险分累积**：同店可上架历史证明非绝对墙，但反复 300015 / 偶发 jar 中毒（`seller/info` 401、`code=-13004`）时建议冷却或换店，**禁止**对同一会话狂刷 create。

## 复测步骤（清 300015 前禁止 batch_create）

```bash
# 在 Mac 仓 /Users/sophiehe/Documents/aginx/aginxbrowser
cargo build --features stealth,screenshot

export AGINXBROWSER_BIND=127.0.0.1:8129
export AGINXBROWSER_STORE_PATH="$HOME/.aginxbrowser/merchant-8129-cache.db"
# 按需：AGINXBROWSER_JS_BUSY_LIMIT_SECS=300
./target/debug/aginxbrowser serve
```

1. 跑 **`xhs-qianfan-login`**，账号用 **`xhs-qf-stable`**，扫码进千帆；确认 `seller/info` 成功（可接受 `deactivated:true`）。
2. 会话 preload **`xhs-sign`**（确认嵌入门闩：`xs_ver`/gate 计数器能涨）。
3. 打开 ark 创建页：`https://ark.xiaohongshu.com/app-item/good/create`（或项目内既定 create URL）。
4. 观察：
   - 门闩：`xs_pr_held≥1`，`xs_pr_blocked`（未签被吞）应合理；
   - **不要**出现未签名 406；
   - **成功标准**：`publish_render` → **HTTP200 + 业务 code200**，创建表单稳定留在 ark，**无** `website-login/error?error_code=300015`。
5. **仅当上一条达标** 再考虑 `batch_create` / 真上架。否则停，留回执，勿喷写接口。

出码 / 登录由主会话按用户口令「出码」操作；本交接不要求子代理自动刷码。
